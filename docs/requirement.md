## 1. プロダクト概要

自分の過去プレイを「録画」し、その再生（**ゴースト**）を足場やスイッチとして使ってゴールを目指す 2D パズルプラットフォーマー。

1 ステージは複数の**ループ**（1 回のプレイ試行）で構成される。ループが終わるたびに「今のプレイを保存するか」を選び、保存した録画は次のループ以降でゴーストとして同時再生される。保存できる本数はステージごとに固定されており、これが実質的な手数制限になる。

**設計上の核心**：プレイヤーは「過去の自分と協力プレイをする」。1 本目でスイッチを踏み続けるだけの録画を取り、2 本目でその開いた扉の先へ進む、といった分担がパズルの解になる。

## 2. スコープ

| 項目 | 内容 |
|---|---|
| ジャンル | 2D パズルプラットフォーマー（1 人用） |
| ステージ数 | 4（Stage 1 はチュートリアル兼用） |
| 1 ループの長さ | 30 秒（全ステージ共通） |
| プラットフォーム | PC（Godot エディタからの実行を想定） |
| セーブ機能 | **なし**（進行状況はアプリ終了で消える） |
| 音 | **なし** |
| 対象外 | 敵キャラクター、オブジェクトの掴み・投げ、ステージエディタ、リプレイの外部保存 |

ゲームジャム作品として、上記「対象外」は意図的にスコープ外としている。

## 3. コアメカニクス要件

| ID | 要件 | 実装 |
|---|---|---|
| C-1 | 録画は**毎プレイ常に**取る。プレイ終了時に保存/破棄を選び、保存したものだけがゴーストとして残る | [RecordingManager.gd](../record/src/scripts/managers/RecordingManager.gd) |
| C-2 | 保存も破棄も、その後はスタート地点からやり直し。自動再開はせず、**Space の明示的な開始入力**を待つ | [Main.gd](../record/src/scripts/game/Main.gd) |
| C-3 | 制限時間は常に存在し、**全プレイ共通の長さ**（30 秒）。これにより全録画が同じ尺になり、再生タイミングがずれない | [LoopManager.gd](../record/src/scripts/managers/LoopManager.gd) |
| C-4 | ゴーストは消えずに蓄積する。保存できる本数はステージごとに固定で、これが手数制限になる | `Level.max_ghosts` |
| C-5 | 失敗しても保存可否を選べる。**破棄は枠を消費しない**ので、1 回のミスで録画を取り直しにならない | `GameManager.discard_ghost()` |
| C-6 | 枠を使い切った状態で保存しようとしたときは、強制リトライにしない。「任意のゴーストを削除して枠を空けて続行」か「タイトルへ戻る」を選べる | `GameManager.trigger_over_limit()` / [HUD.gd](../record/src/scripts/ui/HUD.gd) |
| C-7 | 削除は直前の 1 本に限らず、**保存済みの任意のゴースト**を選んで消せる | `LoopManager.remove_ghost()` |
| C-8 | ゴールに触れた時点で即クリア。時間切れを待たない | `Main._load_level_by_index()` の `Goal.body_entered` |

**枠判定のルール（C-6 の詳細）**：保存を押した時点で「空き枠があるか」で判定する。最後の 1 枠を埋める保存は正常扱いで、**枠が埋まった状態でさらに保存しようとしたときだけ** OverLimit になる。

## 4. ゴーストの挙動ルール

| ID | 要件 | 補足 |
|---|---|---|
| G-1 | ワールドはループのたびに完全リセットする（扉・足場・圧力板を初期状態へ） | リセットは Space 押下時ではなく **IDLE に入った瞬間**に走らせ、保存/破棄/削除を選んだその場で盤面が戻るようにする |
| G-2 | 記録するのは**座標ではなく入力**。物理は固定タイムステップで回し、再生時に同じ物理シミュレーションを再現する | [InputFrame.gd](../record/src/scripts/data/InputFrame.gd) |
| G-3 | 全ゴーストはループ開始 t=0 から**共通クロック**で同時再生する。ゴーストは自分の経過時間を持たない | `LoopManager.loop_tick` |
| G-4 | プレイヤーとゴーストは**同一の物理コードと同一の移動パラメータ**で動く | [ActorBase.gd](../record/src/scripts/actors/ActorBase.gd) ＋ [player_movement.tres](../record/src/data/player_movement.tres) の共有 |
| G-5 | ゴーストは実体を持ち、プレイヤーはその頭に乗って足場にできる | |
| G-6 | ゴーストは**押せない剛体**。後から走るプレイヤーや新しいゴーストに押されて軌道が変わってはならない | 影響を受けるのは常に「新しい側」だけ |
| G-7 | ゴースト同士の衝突は「**自分より前に作られたゴースト**（＝録画当時に存在していた相手）」とだけ行う | 一方向の衝突関係により、各ゴーストの再生は録画時と同じ軌道を必ず再現する |
| G-8 | 動いているゴーストの上に乗ったとき、足場の移動に自然に追従する | `move_and_slide()` のムービングプラットフォーム機能に委ねる |
| G-9 | 録画の尺を超えたゴーストは、**入力なしの状態で物理だけ継続**する（その場で減速して止まり、空中なら落下する） | 範囲外 tick には空の `InputFrame` を返す |
| G-10 | アクターのスポーン位置は全員同一点にせず、ループ番号ごとに横へずらして地面に並べる | 同一点だとゴーストが縦に積み重なる。位置はインデックスで決まるので決定論は保たれる |
| G-11 | ゴールに触れてクリアできるのは**プレイヤーのみ**。ゴーストがゴールを通過してもクリアにならない | `Goal` の `collision_mask` をプレイヤーのみに設定 |
| G-12 | 他のアクターが起こしたワールドの変化でゴーストの進路が塞がれた場合は、**入力をそのまま再生しつつ物理を適用**し、ぶつかれば止まる。この食い違いを解法として要求するステージは作らない | 座標ではなく入力を記録する設計の帰結 |

## 5. ワールド・ギミック要件

| ID | 要件 |
|---|---|
| W-1 | 圧力板は**重みが乗っている間だけ ON**（モーメンタリ）。プレイヤーとゴーストの両方が踏める |
| W-2 | 圧力板は複数のターゲットを同時に操作できる（例：扉とランプを同時に動かす） |
| W-3 | 扉は ON で開き（当たり判定と表示を消す）、OFF で閉じる |
| W-4 | 足場は ON で出現し、OFF で消える。初期状態はインスペクタで選べる |
| W-5 | ランプは ON/OFF を色で示すだけの表示用ギミック。当たり判定を持たない |
| W-6 | はしごの範囲内では重力を無視し、上下入力で昇降できる。範囲は重ねて配置しても正しく動く |
| W-7 | すべてのギミックはループ開始時に初期状態へ戻る |
| W-8 | 新しいギミックは、**決まった名前のメソッドを実装して配置するだけ**で組み込めること（基底クラスやインターフェースの継承を必須にしない） |

ギミックが実装するメソッドは `reset_state()` / `activate()` / `deactivate()` の 3 つ。必要な分だけ書けばよい。手順は [gimmick-guide.md](../record/src/md/gimmick-guide.md)、一覧は [gimmick-list.md](../record/src/md/gimmick-list.md)。

## 6. 操作要件

| キー | 動作 |
|---|---|
| `A` / `D`、`←` / `→` | 左右移動 |
| `W` / `S` | はしごの昇降 |
| `Space` | ジャンプ。IDLE（ループ開始待ち）状態ではループ開始 |
| `R` | ループを中断して終了（リトライ） |
| `K` | 直前のループを録画として保存 |
| `L` | 直前のループを破棄 |
| `E` | `interact` として**録画には残るが、現状これを消費するギミックはない**（将来の拡張用に予約） |

- 保存・破棄・ゴースト削除・次のステージ・タイトルへ戻るは、**キー操作だけでなく画面 UI のボタンからも**行えること。
- 演出中（初回保存の巻き戻し）は入力をロックし、誤操作を防ぐこと。

## 7. UI 要件

| ID | 要件 |
|---|---|
| U-1 | プレイ中は残り時間をカウントダウン表示する（0.1 秒刻み） |
| U-2 | 残りの録画可能回数を、ステージの上限を分母としたバッテリー型メーターで表示する。残量に応じて色を変え（黄緑→黄→赤）、0 のときは赤枠＋斜線にする |
| U-3 | メーター上に残り回数を数字でも重ねて表示する（0 のときは数字を出さない） |
| U-4 | プレイ中であることが分かる録画フレーム UI（四隅の枠・十字・点滅する REC）を表示する |
| U-5 | プレイ終了時は保存/破棄の選択パネルを出し、保存済みゴーストを**ステージの上限本数ぶんのスロット**として並べる。埋まっていない枠は点線で表示する |
| U-6 | 各ゴーストのスロットには録画色のアイコン・通し番号・削除ボタン（×）を表示する |
| U-7 | 枠が満杯のときは保存ボタンを無効化する。削除して空きができたら即座に有効へ戻す |
| U-8 | ゴーストは半透明（α = 0.6）で表示し、録画ごとに異なる色を割り当てて区別できるようにする |
| U-9 | タイトル画面はステージ選択を兼ねる。ステージは `scenes/levels/` を実行時に走査して自動生成する |
| U-10 | 初回は Stage 1 のみ選択可能。Stage 1 をクリアすると全ステージを解放する |
| U-11 | クリア時は「次のステージへ」「タイトルへ戻る」を提示する。次のステージが無ければタイトルへ戻す |

**割り当てる録画色**：赤 → 黄 → 緑 → 青 → 紫 → 白 → 黒（本数が超えたら先頭へ循環）。

## 8. 演出要件

| ID | 状態遷移 | 演出 | 意図 |
|---|---|---|---|
| E-1 | 保存（`ghost_saved`） | 短いノイズ（0.5 秒） | 録画が残ったことを示す |
| E-2 | 破棄（`ghost_discarded`） | ホワイトアウト（一瞬白く→フェード） | 録画が残らないことを示す |
| E-3 | 枠が満杯（`over_limit`） | `MEMORY FULL` テキスト＋画面シェイク | 保存できなかったことを示す |
| E-4 | 初回保存のみ（`rewind_started`） | 長いノイズ（3 秒・入力ロック）＋プレイヤー軌跡の逆再生 | 「時間を巻き戻して録画が残る」というルールを、文字なしで一度だけ明示する |

- E-1〜E-3 は**文字なしでも何が起きたか区別できる**こと。
- E-4 の巻き戻しは、プレイ時間の長短にかかわらず尺を 3 秒に固定する。
- E-4 はアプリ起動後の最初の保存 1 回だけ再生する（フラグは永続化しない）。

## 10. ステージ要件

| ステージ | 録画上限 | 登場ギミック | ねらい |
|---|---|---|---|
| Stage 1 | 3 | Tutorial 看板、Goal | 操作と「録画して足場にする」概念の習得 |
| Stage 2 | 2 | PressurePlate、Door、Lamp、Goal | ゴーストにスイッチを踏ませて扉を開ける |
| Stage 3 | 2 | PressurePlate ×2、Platform ×3、Lamp、Goal | 2 つのスイッチを 2 本の録画で分担する |
| Stage 4 | 1 | PressurePlate ×2、Platform ×4、Ladder ×5、Goal | 1 本の録画だけで複数の役割をこなす |

- ステージは 1 画角（1920 × 1080）に収まるサイズで設計し、カメラは固定（`Camera2D` を使わない）。
- 各ステージは初回プレイでは**物理的にゴールへ到達できない**ように設計する。
- ステージの追加は `scenes/levels/Level005.tscn` を置くだけで成立させる（コード変更を不要にする）。
- 録画上限はステージルートの `max_ghosts` としてインスペクタから設定する。

## 12. 当初設計からの差分

初期の要件・仕様案から変更、または見送った項目。**現状は「現状」列が正しい。**

| 項目 | 当初案 | 現状 | 理由 |
|---|---|---|---|
| 実装言語 | C#（.NET） | **GDScript** | ジャム開発の反復速度を優先。`project.godot` に `[dotnet]` セクションが残っているが未使用 |
| 掴む・投げる（`E`、`W`+`E` で上投げ） | あり | **未実装** | `interact` の入力は録画に残るが、消費するギミックがない |
| 敵キャラクター（最寄りのアクターを狙う） | あり | **未実装** | スコープ外 |
| 同一オブジェクトの掴み競合ルール | あり | **該当なし** | 掴み自体が未実装のため |
| 各ゴーストの軌跡プレビュー | 常時表示 | **未実装** | 代わりに初回保存時の巻き戻し演出でのみ軌跡を見せる |
| ゴーストの色 | 赤・橙・黄・緑・青・紫・白・黒（8 色） | **7 色**（橙を除外） | 橙は赤・黄と紛らわしいため無効化 |
| ギミックの共通化 | `IGimmickResettable` / `IActivatable` インターフェース | **メソッド名によるダックタイピング**（`has_method()`） | GDScript にインターフェースがなく、継承を強制しないほうが追加が軽いため |
| 扉の条件 | `TwoButtonDoor`（2 つのスイッチの AND） | **単一トリガー**。1 つの `PressurePlate` が `target_paths` の全ターゲットを操作する | 現行ステージで AND 条件が不要だったため |
| ステージ設定 | `level_configs/level_001.tres` リソース | **`Level.gd` の `@export var max_ghosts`** | ステージ固有の設定が 1 項目のみで、リソース化が過剰だったため |
| アクターのシーン | `Actor.tscn` 1 つを共用 | **`PlayerActor.tscn` / `GhostActor.tscn` の 2 つ** | 衝突レイヤーと初期色が別なため。物理コードは `ActorBase.gd` で共有している |
| 接地判定 | 足元を薄く探る `FloorDetector`（ShapeCast2D）で判定 | **`is_on_floor()`（Godot 標準）** | `move_and_slide()` のムービングプラットフォーム機能で足場追従が解決したため。`FloorDetector` ノード自体は残っており、ゴーストごとの衝突マスクを揃える対象になっている |
| 衝突レイヤー | Layer 8 = Object、Layer 9 = Sensor を確保 | **未使用**。World / Player / Ghost_0〜3 のみ | 掴めるオブジェクトが未実装のため。センサー類は `collision_layer = 0` + マスクで運用 |
| ワールドリセットのタイミング | ループ開始時（Space 押下時） | **IDLE に入った時点** | 保存/破棄/削除を選んだその瞬間に盤面が戻り、Space 後にリセットが走る違和感を消すため |
| ループ枠 | 部屋ごとに固定（例：4 回） | **ステージごとに 3 / 2 / 2 / 1** | 実際のステージ設計に合わせた |
| スポーン間隔 | 48 px | **64 px** | アクターの当たり判定（128 px 幅）に合わせて調整 |
| 枠を使い切ったときの選択肢 | ゴースト削除 / 部屋リトライ | **ゴースト削除 / タイトルへ戻る** | 専用の部屋リトライ UI を持たず、`R` でのループ中断とステージ選択に集約した |
| ディレクトリ | `scripts/`、`scenes/game/Main.tscn` | **`src/scripts/`、`scenes/Main.tscn`** | — |
| 制限時間 | 未定 | **30 秒** | — |

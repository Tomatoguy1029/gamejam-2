# テスト一覧

書き方・粒度の方針・実行方法は [testing.md](testing.md) を参照。

---

## 1. 一覧

| ファイル | 件数 | 何を守っているか |
|---|---|---|
| `test_harness.gd` | 3 | ハーネス自身の自己確認（発見・実行・`await`・集計） |
| `test_debug_launch.gd` | 12 | `DebugLaunch` の予約 / **1回で消費**（F5 に漏れない）/ パス→ステージ番号 / フォールバック規則。**別プロセスを起動して `user://` の受け渡しが成立することも確認する** |
| `test_main_debug_launch.gd` | 11 | `Main` の起動分岐。予約があればそのステージへ直行、無ければ**タイトルのまま（F5 の挙動）**。存在しないステージの退避 |
| `test_debug_menu.gd` | 28 | メニューの開閉と `input_locked` 連動 / 演出中は開かない / ショートカットの差し替え / 登録 API 6種 / パネルのレイアウト（画面を覆わない・はみ出さない・折り返す） |
| `test_debug_menu_items.gd` | 17 | メニュー項目の実挙動。ステージ移動、ゴースト数変更、**保存済み本数より上限を小さくしても HUD が壊れない**、状態表示 |
| `test_debug_plugin.gd` | 5 | プラグインの配線。`plugin.gd` が解析できる / `plugin.cfg` の必須キー / `project.godot` で有効化されている |

## 2. 何を見たいときにどれを使うか

| 見たいこと | 使うもの |
|---|---|
| 変更が既存を壊していないか | `./run_tests.sh`（全部） |
| デバッグ起動が F5 に漏れていないか | `test_debug_launch.gd` / `test_main_debug_launch.gd` |
| メニューに項目を足して壊れていないか | `test_debug_menu.gd`（登録 API とレイアウト） |
| メニューからの操作がゲームに効いているか | `test_debug_menu_items.gd` |
| プラグインがエディタで読めるか | `test_debug_plugin.gd` |
| ハーネス自体が動いているか | `test_harness.gd` |

## 3. 現状の穴

**テストはデバッグ機能に偏っている。ゲーム本体のテストはまだ無い。**

未カバーで、書く価値が高いと考えられるもの:

- **録画と再生の一致**（`InputFrame` → `GhostController` → 同じ軌道になるか）。設計の核心なので最優先
- **ゴーストの一方向衝突**（`LoopManager._set_ghost_collision()` のマスク計算）
- **ギミック**。滑車は開発時にヘッドレスで検証したが、使い捨てだったのでテストとして残っていない
- **ワールドリセット**（`WorldResetManager` の再帰走査）

これらは実装が固まっているぶん壊れにくいが、壊れたときの被害が大きい。手を入れる予定ができた時点でテストを先に足すのが望ましい。

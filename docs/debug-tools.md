# デバッグツール

開発中に使う機能をまとめたドキュメント。**製品ビルドには含まれない**（すべて `OS.has_feature("editor")` でガードする）。

## 運用ルール

- **デバッグツールを作ったら、このファイルに使い方の短い説明を追記する。** 起動方法・操作・できること、の3点が分かれば十分
- 仕様書や設計メモといった作業用ドキュメントは `docs/wip/` に置く。**`docs/wip/` は `.gitignore` 済みでコミットされない**
- リポジトリにコミットするデバッグ関連のドキュメントは、原則このファイルだけにする

## ツール一覧

### デバッグ実行（Debug Launcher）

- **起動方法**: Godot エディタのツールバーにある **「▶ Debug」** ボタンを押す。編集中のレベルシーンがそのまま立ち上がる
- **できること**
  - 編集中の `LevelNNN.tscn` へ直行する（タイトル画面とステージ解放を飛ばす）
  - 実行中に **`Esc`** でデバッグメニューを開き、**他のステージへ移動**できる
  - 同じメニューで**使えるゴーストの数**を変えられる
  - 現在のステージ / `GameState` / 保存済みゴースト数を確認できる
  - レベル以外のシーン（`Pulley.tscn` など）を開いて押した場合は、直前にデバッグ起動したステージで立ち上がる（それも無ければ Stage 1）
- **注意点**
  - **`F5`（通常実行）の挙動は変わらない。** タイトル → Stage 1 → クリアで全解放、のまま。デバッグ起動の予約は1回で消費される
  - エディタから実行したときだけ有効。製品ビルドではメニューごと存在しない
  - ボタンを押すと、編集中のシーンは**自動保存される**
  - 巻き戻し演出などで入力がロックされている間は開かない（演出のロックを横取りしないため）
  - ゴースト数を変えると、その場で盤面がリセットされる（IDLE 中はアクターが再配置される）

**ショートカットを変える**

`scenes/ui/DebugMenu.tscn` を開き、ルートの `Toggle Menu Shortcut` にインスペクタから好きなキーを割り当てる。空にすればキーでは開かなくなる。

> ファンクションキー（`F3` など）は OS 側のショートカットに取られることがあるので既定にしていない。

**ショートカットを増やす**

`DebugMenu.gd` に `@export var <名前>_shortcut: Shortcut` を足し、`_build_shortcuts()` に `_bind(<名前>_shortcut, <処理>)` を1行足す。割り当てはインスペクタから行う。project.godot の入力マップは使わない（製品側の設定にデバッグの痕跡を残さないため）。
